# Chapter 33: Platform Architecture

> The end-to-end design of the RNA-seq analysis platform: how the
> bioinformatics pipeline, backend API, database, and user interface fit
> together into one system.

---

## 1. What is it?

The **platform architecture** describes the overall structure of the
whole application: how sequencing data flows from raw reads through
analysis to an interactive UI. It is the blueprint that ties every
prior chapter together.

We build in **4 layers** (from `00_project_overview.md`).

---

## 2. Why do we need it?

- A single tool isn't enough -- the pipeline must be operated,
  monitored, and explored.
- Separating layers (data / logic / presentation) makes the system
  maintainable, testable, and scalable.
- It turns the bioinformatics pipeline into a usable **product**.

---

## 3. Where does it fit?

```
Layer 4: User Interface (React, Ch 35)
```

## 6. How it works (the 4 layers)

### Layer 1 -- Bioinformatics Engine

Runs the pipeline tools (FastQC, fastp, STAR, Salmon, featureCounts,
DESeq2). Produces results files.

### Layer 2 -- Workflow Engine

Nextflow orchestrates and containerizes Layer 1, on local / SLURM /
AWS.

### Layer 3 -- Application / API

**FastAPI** serves results to the frontend via HTTP endpoints and
stores metadata (projects, samples, runs, results) in **SQLite**
(SQLAlchemy).

### Layer 4 -- User Interface

**React + TypeScript + Tailwind** renders dashboards, QC plots,
results tables, and pathway views, calling the API.

Data flows **down** (jobs) and results flow **up** (API -> UI).

---

## 7. Biology behind it

- The "biology" lives in Layer 1 (the tools); the platform layers make
  that biology accessible.
- Results (DE, pathways) are generated by the pipeline and surfaced to
  users through the API/UI.
- Good architecture keeps the biological analysis reproducible.

```bash

# Start the UI (Phase 2)
cd ui
npm install
npm run dev
```

## 10. How to read the output

- **UI** (`http://localhost:5173`) shows results.
- **API** (`http://localhost:8000/docs`) documents all endpoints.
- Each layer is independently testable and swappable.

---

## 11. Common errors

| Error | Fix |
|-------|-----|
| UI can't reach API | Check CORS / API base URL |
| Missing results | Pipeline (Layer 1) must run first |
| DB schema drift | Run migrations (Alembic) |
| Port conflicts | Use distinct ports for UI/API |

---

## 12. Limitations

- Adding full UI-triggered execution needs Nextflow + API integration
  (deferred).
- SQLite is single-user/small-scale; production would use Postgres.
- 4 layers add complexity vs a simple CLI pipeline.
