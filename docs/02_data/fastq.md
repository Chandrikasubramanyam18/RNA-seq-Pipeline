# Chapter 04: FASTQ Format

> The raw output of sequencing and the primary input to the entire
> RNA-seq pipeline. Understanding FASTQ is essential for QC,
> preprocessing, and alignment.

---

## 1. What is it?

**FASTQ** is a text-based file format that stores both the **nucleotide
sequence** of each read and the **per-base quality score** for every
nucleotide.

Each sequencing read is represented by a **4-line block**:

```
@<identifier>
<sequence>
+
<quality scores>
```

- **Line 1**: Read identifier (`@...`)
- **Line 2**: The nucleotide sequence (A, C, G, T, N)
- **Line 3**: A separator (`+`, sometimes repeats the identifier)
- **Line 4**: Quality scores, one ASCII character per nucleotide

Almost all RNA-seq data is stored as **gzip-compressed FASTQ**
(`.fastq.gz`) to save space.

---

## 2. Why do we need it?

FASTQ is the **standard input format** for virtually every
bioinformatics tool:

- FastQC reads it for QC
- fastp reads it for trimming
- STAR/Salmon read it for alignment/quantification
- The `data/raw/` directory contains the raw FASTQ files

If you cannot read a FASTQ file correctly, you cannot run any
downstream analysis. Errors in parsing FASTQ (wrong quality encoding,
corrupted gzip, mismatch in paired files) are common sources of bugs.

---

## 3. Where does it fit?

```
RNA-seq (Ch 03) -> FASTQ files   <--- we are here
                      |
                      +--> FastQC (Ch 08)
                      +--> fastp   (Ch 09)
```

## 5. Output

FASTQ is itself an input/output format. Derived outputs include:

- **Trimmed FASTQ** (from fastp): `data/processed/*_trimmed_R{1,2}.fastq.gz`
- **QC summaries** (from FastQC parser): TSV tables
- Largely, FASTQ is consumed to produce BAM (Chapter 06) and counts
  (Chapters 14-15).

## 6. How it works

### 6.1 Anatomy of a FASTQ record

Here is a real example (63 bp read from our dataset):

```
@SRR1039508.1 HWI-ST1182:144:D1DVKACXX:5:1101:1234:2145 length=63
NTGACCGTTAGGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTA
+
#<<BBFFFFFFFGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGG
```

- `@SRR1039508.1` is the read identifier
- The second line is the sequence (63 bases)
- The `+` line is the separator
- The fourth line is the quality string (must be the same length as
  the sequence)

### 6.2 Pairing in paired-end data

Each fragment produces **two** records (R1 and R2). They have related
identifiers and must appear in the **same order** in both files so
that position *i* in R1 corresponds to position *i* in R2.

The samplesheet defines which R1/R2 files pair together for each
sample.

### 6.3 Phred Quality Scores

Every sequenced base has a quality score reflecting the probability
the base was called incorrectly.

The formula:

```
    Q = -10 * log10(P)
```

where `P` is the probability of error.

| Q score | Error probability | Base call accuracy |
|---------|-------------------|--------------------|
| Q10 | 1 in 10 (0.1) | 90% |
| Q20 | 1 in 100 (0.01) | 99% |
| Q30 | 1 in 1,000 (0.001) | 99.9% |
| Q40 | 1 in 10,000 (0.0001) | 99.99% |

### 6.4 ASCII Encoding of Quality

Quality scores are stored as a single ASCII character per base using
the **Phred+33** encoding (the modern standard):

```
ASCII character = Q + 33
```

So:
- Q = 0  -> ASCII 33 (`!`)
- Q = 20 -> ASCII 53 (`5`)
- Q = 30 -> ASCII 63 (`?`)
- Q = 40 -> ASCII 73 (`I`)

In the example above, the quality string `#<<BBFFFFF...` encodes
scores. `#` = 35 - 33 = Q2, `B` = 66 - 33 = Q33, `F` = 70 - 33 = Q37,
`G` = 71 - 33 = Q38.

### 6.5 The Sequence Line

The sequence line contains the nucleotides. `N` indicates an
ambiguous/unknown base. G/C content affects GC bias stats in FastQC.

### 6.6 gzip Compression

FASTQ files are large and are almost always gzipped (`.fastq.gz`).
Tools handle the decompression transparently.

---

## 7. Biology behind it

- The **sequence** is the actual genetic read from the sample.
- The **quality** reflects how confident the sequencer is at each
  position -- needed because sequencing introduces errors.
- Low-quality positions (especially toward the 3' end) cause
  alignment mistakes and need trimming (Chapter 09).
- **N** bases are ambiguous; high N content indicates technical
  problems.

## 8. Command

Our implemented scripts handle FASTQ:

```bash
# Run FastQC on raw FASTQ files
bash scripts/run_fastqc.sh --input data/raw --output results/fastqc/raw --threads 4

# Summarize FastQC metrics into a TSV
python3 scripts/python/summarize_fastqc.py \
    --input-dir results/fastqc/raw \
    --output results/fastqc/raw/fastqc_summary.tsv

# Validate the samplesheet (checks FASTQ extensions, paths, pairs)
python3 scripts/python/validate_samplesheet.py metadata/samplesheet.csv --check-files-exist
```

You can also peek directly at a FASTQ file:

```bash
# Look at the first 8 lines (2 reads) of a gzipped FASTQ
zcat data/raw/SRR1039508_1.fastq.gz | head -n 8
```

## 9. Example

Read the first read of C1's forward file (conceptually):

```
@SRR1039508.1 ... length=63
NTGACCGTTAGGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTAGCTA
+
#<<BBFFFFFFFGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGGG
```

- First base is `N` (low Q2, `#`) -- poor first base, common artifact
- Most bases are Q33+ (`F`, `G`) -- high quality
- The `Q` decreases slightly toward the 3' end (typical)

This pattern (good middle, slight 3' decline, occasional bad 1st base)
is what FastQC expects to see.

---

## 10. How to read the output

When you open a FASTQ file (or its QC summary):

| Field | What to check |
|-------|---------------|
| Read length (63 in our case) | Consistent across all reads (before trimming) |
| Quality scores | Mostly Q30+; droops at 3' end are normal |
| Sequence line | Real nucleotides; check GC content |
| N bases | Should be rare; high N = degradation/errors |
| Paired order | R1 and R2 must have matching identifiers in order |

---

## 11. Common errors

| Error | Cause | Fix |
|-------|-------|-----|
| **Phred encoding mixup** | Phred+33 vs +64 (old Solexa) | Use modern Phred+33; verify encoding |
| **Paired files misaligned** | Sample mix-up or sorting | Validate with samplesheet / tools |
| **Corrupt gzip / truncation** | Incomplete download | Re-download and MD5 check |
| **Empty/corrupt FASTQ** | Failed write | Check `gzip -t file.fastq.gz` |
| **Wrong R1/R2 labeling** | Filename/order error | Cross-check with pairing |

---

## 12. Limitations

- FASTQ is **uncompressed-in-practice** (though gzipped) and huge.
- It stores no genomic coordinates until aligned (that's BAM).
- Ambiguous `N` bases provide no biological information.
- Quality is a statistical estimate, not ground truth.
